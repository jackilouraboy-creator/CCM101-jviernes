
# Final Reflection: From Mission 1 to Mission 10
When we started Mission 1, "the cloud" was just a word to us. We knew it had something to do with storing files online, but we did not really know what was behind it. Mission 1 showed us that the cloud is made of real things like servers, networks, and software that someone has to set up and take care of. At that point we were mostly following steps and hoping they worked.
As the missions went on, the lessons stacked on top of each other. We learned how virtual machines work, how to move around a Linux system using the command line, how machines talk to each other over a network, and why security and backups matter. For us, the most important thing we got from these missions was not one single tool. It was getting used to reading what the terminal tells us, trying again, and not panicking when something fails.
Mission 10 was the first time we had to put everything together by ourselves, and honestly the problems taught us more than the steps did.
A server needs an address that does not change. After we rebooted our VM, its IP address changed and our SSH connection stopped working. We tried to fix it from the router, but our account on the router could not reserve an address. So we set a static IP inside Ubuntu using netplan. We realized that a server is only useful if people can always find it.

Containers make deployment repeatable. With one docker-compose.yml file, we started WordPress and MySQL together on a private network. After a reboot, our site still had its content because the data was saved in volumes. Now we understand the difference between a container, which can be thrown away, and the data, which has to be kept.
Security is about what you keep closed.We set UFW to deny everything by default and only opened ports 22 and 80. We also learned that Docker has its own firewall rules, so the safest way to protect our database was to never publish its port at all.
Automation saves you from forgetting.We wrote a backup script and scheduled it with cron. Seeing it run by itself every minute during our test was a good feeling for us. We also found out that cron follows the server's clock, so we had to change the timezone to make the schedule match our local time.
Mistakes are part of the work. We forgot our password and had to get back in through GRUB. We also made typos in file names and commands. Every time, the error message told us what was wrong if we read it carefully, and that became a habit for me.
Documentation matters too. Writing the operational manual made us check every step again, because someone else has to be able to follow it without us. We learned that a system only we understand is not really finished.

Before, We was afraid of breaking things. Now we know that a broken setup usually tells us why it broke, and that we can fix it if we stay calm and read the message. We are still not experts and we still look things up a lot, but we can build, secure, and maintain a small system on our own, and we could not say that at the start.If we could keep working on this project, we would add HTTPS, switch SSH to key login instead of a password, copy the backups to another machine, and monitor the containers. We think those steps would make it closer to something a real client could depend on.We am thankful for this course. It made the cloud feel less scary, and it made us want to learn more.
